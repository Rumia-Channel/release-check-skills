# release-check-skills

**機能の設計意図・正常性・互換性・回帰（リグレッション）を、証拠と網羅性台帳に基づいて検証するAIエージェント用スキル**です。

[Cloudflare security-audit-skill](https://github.com/cloudflare/security-audit-skill) の「対象範囲を明示する」「発見した候補を独立検証する」「未確認事項を隠さない」という考え方を、**セキュリティ監査ではなくリリース前の機能品質確認**に応用しています。

## 何ができるスキルか

コードベースに対し、次の問いを分けて調査します。

| 確認したいこと | スキルの動作 |
| --- | --- |
| **どんな機能がある？** | CLI・API・UI・設定・ジョブ・永続化などの外部から意味のある機能を列挙し、入口や依存関係を記録します。 |
| **なぜ作られた？** | 仕様書、README、既存テスト、変更履歴、ソースコードを突き合わせて「目的」「期待動作」「根拠」を整理します。明記された意図・推定・不明を区別します。 |
| **正常に動く？** | 実際の入力・結果に基づき、正常系、境界値、異常系、統合、互換性、ライフサイクルの6観点で調べます。 |
| **変更で壊れていない？** | 指定された **BASE（変更前）と HEAD（変更後）** を同条件で比較し、検証できた回帰、不具合、意図された変更、判断保留を区別します。 |
| **どこまで確かめた？** | 機能ごとのカバレッジ台帳に、検証済み・失敗・未実行・ブロック・対象外を記録します。 |
| **リリースしていい？** | 検証済みの破壊的変更と残余リスクを示し、リリース判断の材料となるレポートを生成します（リリースの最終承認は行いません）。 |

**重要:** 「テストが成功した」ことと「すべての機能が壊れていない」ことを同一視しません。また、HEADで失敗しただけでは回帰とは断定せず、BASE側で成立していた動作の証拠を確認します。

## インストール（npx skills）

Node.js・npm が利用できる環境で、スキルを使いたいプロジェクトのディレクトリから実行します。インストール対象のAIエージェントは Skills CLI の案内に従って選択してください。

### プロジェクト単位でインストール

```bash
npx skills add https://github.com/Rumia-Channel/release-check-skills --skill release-check
```

### ユーザー全体で利用（グローバル）

```bash
npx skills add https://github.com/Rumia-Channel/release-check-skills --skill release-check --global
```

### インストール後の確認と更新

```bash
# 現在のプロジェクトにインストールしたスキルを確認
npx skills list

# グローバルにインストールしたスキルを確認
npx skills list --global

# インストール済みスキルを更新
npx skills update
```

GitHub URLの代わりに `npx skills add Rumia-Channel/release-check-skills --skill release-check` も使用できます。指定エージェントへの導入など、CLIの最新オプションは [Skills CLI公式ドキュメント](https://www.skills.sh/docs/cli) を参照してください。

### 手動インストール

Skills CLIに対応していない環境では、`skills/release-check/` ディレクトリ全体を、利用中のエージェントが読み取れるスキルディレクトリにコピーしてください。 `SKILL.md` だけでなく参照ドキュメントと `scripts/` も必要です。

## 使い方

導入後、対応するコーディングエージェントを監査対象リポジトリで起動し、例えば次のように依頼します。

```text
このリポジトリに実装されている機能を洗い出し、
各機能の目的と期待動作、根拠となるソースや仕様を整理して。
```

```text
このリポジトリの機能を包括的に監査して。
正常系、境界値、異常系、統合、互換性、ライフサイクルの網羅性を確認し、
未検証事項も含めてレポートを作成して。
```

```text
前回リリースの v1.2.0 を BASE、HEAD を比較対象として、
機能の破壊や後方互換性の問題がないか回帰監査して。
各機能の設計意図と、BASE/HEADの観測結果を根拠付きで示して。
```

質問や限定調査では **guidance mode**、包括的な監査やレポート生成を明示した場合は **full audit mode** を使用します。監査対象、比較基準のコミット・タグ、必要なプラットフォーム、対象外の領域を指定すると、結果を解釈しやすくなります。比較可能なBASEがない場合、現行の機能検査は可能ですが「確定した回帰」とは判定しません。

## 監査の流れ

1. **機能と意図の発見:** 公開インターフェース・仕様・テスト・履歴を調査し、根拠付きで機能一覧を作成。
2. **網羅性台帳の作成:** 各機能に6つの必須検証軸を割り当て、追加すべきシナリオと対象外理由を記録。
3. **動作検証・差分比較:** 実行可能な安全なテストから観測し、必要に応じBASEとHEADを比較。
4. **独立検証:** 発見者とは別の検証者が、破壊的変更の候補を反証する観点で再評価。
5. **整合性検査:** 構造化された監査データのID、参照、状態、必須項目をNode.jsスクリプトで検査。
6. **報告:** 確定した問題、設計意図、未検証領域、リリース判断上のリスクをまとめる。

## 生成される監査成果物

full auditでは、対象リポジトリ外の新しい出力先（標準では `~/release-check-skills/<repo>/run-<N>/`）に生成します。

| ファイル | 内容 |
| --- | --- |
| `audit.json` | 実行条件、機能カタログ、6観点のカバレッジ、証拠、検証済みの判定を一元管理するJSON |
| `REPORT.md` | 機能の目的・正常性・回帰・未確認事項・リリース判定材料をまとめた人間向けレポート |
| `EVIDENCE/` | 必要な場合のみ保持する最小限の、秘密情報を含まないテスト証拠 |

判定は `confirmed_regression`（確定した回帰）、`confirmed_change`（確認された動作変更）、`needs_validation`（追加検証が必要）、`rejected`（反証された候補）を区別します。

## 検証スクリプト

スキルには外部依存のないNode.js製バリデーターが含まれています。**次のコマンドは、このリポジトリをクローンした場所から実行する例**です。

```bash
# 監査結果の構造と相互参照を検査
node skills/release-check/scripts/validate-audit.cjs /path/to/audit.json

# バリデーター自身のテスト
node --test skills/release-check/scripts/validate-audit.test.cjs
```

バリデーター自体はNode.js 18以降を想定しています。インストールに用いる `npx skills` のNode.js要件は別途、[Skills CLIの公式案内](https://github.com/vercel-labs/skills) を確認してください。

**構造検証の成功は、観測結果や根拠が真実であることを保証しません。**

## 安全性・制約

- 監査対象リポジトリのビルド、テスト、スクリプトなどは、外部ネットワークを遮断し、書き込み範囲・環境変数・資源を制限した **OSレベルのサンドボックス**が用意できる場合にだけ実行します。用意できない場合はブロック理由を報告し、実行したと偽りません。
- 対象プロジェクトのコード変更、依存パッケージの勝手なインストール、本番環境への通信、デプロイやリリースは行いません。
- 独立した検証エージェントを利用できない場合は独立検証済みだと主張せず、未検証事項として残します。
- 「監査完了」は **発見して登録した対象範囲について、必須の検証観点が説明・確認された**という意味です。未知の機能やすべての環境での不具合不在を証明するものではありません。

## スキルの内部仕様

- [SKILL.md](skills/release-check/SKILL.md) — 起動条件・実行制約・全体の監査プロトコル
- [FEATURE-DISCOVERY.md](skills/release-check/FEATURE-DISCOVERY.md) — 機能と意図の復元、網羅性の定義
- [BEHAVIOR-AND-REGRESSION.md](skills/release-check/BEHAVIOR-AND-REGRESSION.md) — 動作検証・BASE/HEAD比較・反証
- [DATA-CONTRACT.md](skills/release-check/DATA-CONTRACT.md) — `audit.json` のデータ契約
- [REPORTING.md](skills/release-check/REPORTING.md) — レポート・完了基準
